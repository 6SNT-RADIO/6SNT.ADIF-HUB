Use cases

When do you need it?

For any operator who has ever had to merge, clean or convert logs before importing them somewhere that matters.

Scenario 01
Merging logs from different software
Log4OM export + N1MM Cabrillo + WSJT-X ADIF. Different fields, different date formats, overlapping QSOs.
Scenario 02
Cabrillo to ADIF conversion
Contest logs need to become ADIF before uploading to LoTW, QRZ or ClubLog. Generic converters lose fields.
Scenario 03
Duplicate QSOs with small differences
Same QSO logged twice with 1-minute offset or different RST. Identify and resolve before importing.
Scenario 04
Recovering old spreadsheet logs
Years of QSOs in Excel or CSV format. Map columns to ADIF fields and get a clean export.
Scenario 05
FT8 log cleanup
WSJT-X logs accumulated across sessions and computers. Normalize before merging into a master log.
Scenario 06
Pre-import review
Inspect what is actually in a file before touching a clean main logbook or uploading to LoTW.
Workflow

Six steps. One clean ADIF.

Work only with copies during beta. Review every conflict that matters. Export when ready.

01
Import one or more log files
Drop in any supported format. Mix formats freely — the hub handles the differences.
ADI · ADX · CBR · CSV · XLSX · JSON
02
Normalize fields toward ADIF 3.1.7
Date formats, band names, mode strings and field names are standardized automatically.
03
Review column mapping
When the source file is ambiguous, map columns manually before processing.
04
Deduplicate with contextual rules
Identify duplicate QSOs with tolerance for small time offsets or RST differences.
05
Resolve conflicts by field or strategy
Choose which source wins field by field, or apply a bulk strategy. Every decision is visible.
06
Export a consolidated ADI file
One clean ADIF for manual review and downstream tools. The original files are untouched.
